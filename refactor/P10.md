# P10 — Ship it

**Status:** in-progress **Started:** 2026-05-06 **Landed:** —

P10 is the final hygiene pass after P9 lands the architectural truth.
Small, mostly mechanical. Closes the refactor.

## Scope

### 1. Saved-state cleanup + injectable constructor (landed)

Path A landed alongside Thread 2 in one edit.

**Thread 1: drop the doc lie.** `crates/core/src/state.rs` shrunk
from ~340 LOC to ~190 LOC. `PersistedSettings` (the 10-bool toggle
overlay) and the legacy field migration retired entirely; settings
no longer round-trip through JSON. `state::save_settings`,
`update_settings`'s persistence call, and the legacy
`vim_enabled` / top-level `show_thinking` migration paths all
deleted. `State` renamed to `SessionCache` with just the
genuinely cache-shaped fields: `mode`, `selected_model`,
`reasoning_effort`. `accent_color` dropped — themes are config,
they live in `init.lua` (the `/theme` and `/color` runtime pickers
are previewers; persistence comes from editing your config).

`ResolvedSettings` moved from `state.rs` to `core/config.rs`
alongside `SettingsConfig`, where it conceptually belongs.
`SettingsConfig::resolve(&self) -> ResolvedSettings` collapses the
two-phase merge into one direct call (no more
`PersistedSettings::resolve(&SettingsConfig)`).

**Thread 2: `TuiApp::new` is state-injectable.** Constructor now
takes `cache: SessionCache` as its final parameter; the internal
`state::State::load()` call is gone. `main.rs` calls
`SessionCache::load()` once via `startup::resolve` and threads it
through `ResolvedStartup` to `TuiApp::new`. Constructor is pure
modulo the `Ui::new() + terminal_size` setup — no filesystem
touch, no global state read.

Net: `state.rs` shrank ≥ 50%; the doc claim "all config in
`init.lua`" is true at the file level; `TuiApp::new` is
disk-clean and ready for L3 storybook fixture construction.

### 2. P10.2 — audit-driven cleanup batch (landed)

End-of-refactor audit (2026-05-06) found a handful of dead surfaces and
modularity wins worth landing before the parity walk. Investigated
each by call-tracing static usage; the items below are the ones whose
removal/regrouping makes the tree strictly simpler without losing
functionality. Landed in commit `74222857`.

- **A1 — Dead PredictInput / InputPrediction path ✅.**
  `predict.lua` drives input prediction through
  `smelt.engine.ask({task = "prediction"})` +
  `smelt.ui.ghost_text.set`. The parallel `UiCommand::PredictInput`
  / `EngineEvent::InputPrediction` / `spawn_predict_request` /
  `predict_generation: u64` / `handle_input_prediction` chain was
  unreachable (zero senders workspace-wide); deleted the variants,
  the engine spawn, the TuiApp field, and both engine-event arms.
- **A2 — `engine::tools::Tool` trait + ToolRegistry body ✅.**
  Live tool dispatch is `McpDispatcher` (impls `ToolDispatcher`
  directly) plus the Lua-tool channel via `UiCommand::ToolDispatch`.
  `ToolRegistry` (60 LOC) replaced with a small `EmptyDispatcher`
  used only by `main.rs:369` as the no-MCP fallback; `Tool`,
  `ToolEntry`, `ToolEntry::is_mcp`, `register_mcp`, `build_tools`,
  `ToolRegistry::get` deleted.
- **A3 — Unused `#[allow(dead_code)]` methods ✅.**
  `BlockBufferCache::invalidate`, `BlockBufferCache::total_rows`,
  `BlockHistory::status`, `BlockHistory::tool_block_id` deleted
  along with their allow attributes.
- **B1 — `permissions: Arc<Permissions>` to Core — declined.**
  Audit recommendation considered; field stays on `TuiApp` for now.
  No concrete consumer (no `HeadlessApp` permission-enforcing path
  is in flight, no Host-tier Lua binding caller). Revisit if a
  consumer materializes.
- **B2 — Group cmdline state ✅.** Four `TuiApp` fields used only
  by `app/cmdline.rs` (`cmdline_history`, `cmdline_history_browse`,
  `cmdline_history_stash`, `cmdline_completer`) collapsed to one
  `CmdlineState` struct (`crates/tui/src/app/cmdline.rs:28`)
  exposed as `app.cmdline`.
- **C1 — Box `UiCommand::StartTurn` payload ✅.** New
  `StartTurnPayload` boxed into the variant
  (`UiCommand::StartTurn(Box<StartTurnPayload>)`). Drops the
  `large_enum_variant` allow; shrinks the enum size for every
  other variant the channel ferries.
- **D1+D2 — Stale phase-label and "legacy" comment sweep ✅.**
  Stale references in `core/src/runtime.rs`, `core/src/grep.rs`,
  `core/src/lua/api/shell.rs`, `engine/src/lib.rs`,
  `tui/src/app/cmdline.rs`, and the `intern_anonymous_style`
  comments in `core/src/buffer.rs` / `core/src/theme.rs` rewritten
  to describe current behaviour rather than migration history.
  `core/src/session.rs:312` (meta.json sidecar backfill) preserved
  — that's real backwards-compat for users with pre-meta sessions
  on disk.
- **E1 — Transcript stack fold — considered, declined.** Initial
  audit flagged the transcript stack (`BlockHistory` +
  `StreamParser` + `TranscriptSnapshot` + `BlockBufferCache` +
  `TranscriptProjection`, ~4640 LOC) as a candidate for folding
  directly onto `Buffer` + `BufferParser`. Closer inspection
  showed the layers each carry load: `BlockHistory` is the
  semantic SoT, `StreamParser` produces the Block intermediate,
  per-Block parsers paint into per-block sub-Buffers
  (content-keyed cache), `TranscriptProjection` copies into the
  display Buffer once per `(generation, width)`,
  `TranscriptSnapshot` is a parallel projection that carries
  per-cell `SpanMeta` for selectable / `copy_as`-aware copy. The
  "duplication" with the display Buffer exists because `Buffer`
  doesn't carry per-cell `SpanMeta` and adding it would bloat
  every Buffer. Folding either drops the SpanMeta-aware copy
  feature or relocates the same logic onto `Buffer` — neither is
  a simplification. P9.c stage 1 (per-Block parsers under
  `transcript_parsers/`) + P9.r (`BlockLayout` return shape)
  already landed the tractable share of the keystone.

### 4a. L3-prim storybook lands ✅

`crates/tui/tests/storybook/` ships with the harness (`StoryCtx`,
`Ui::snapshot`, `SnapshotFrame`, `story!` macro) and 58 stories
across 6 groups (`buffer`, `chrome`, `layout`, `overlays`,
`theme`, `vim`). Two snapshot files per story (`<id>.snap` text +
`<id>.styles.snap` per-cell style sidecar) keep colour-only and
wrap-only diffs surgical; `insta` is the existing snapshot library.

Interactive viewer: `crates/tui/examples/stories.rs` reads the
blessed `.snap` files and renders each story's frame with its
styles sidecar applied — no story re-execution. Run with
`cargo run -p tui --example stories`. `j`/`k` or `↓`/`↑`
navigate, `g`/`G` jump to top/bottom, `q` or `Esc` quits.

Three additive seams landed alongside:
- `Ui::snapshot(&mut self) -> SnapshotFrame` — renders into the
  compositor through an `io::sink()` writer, returns a structured
  copy of the resulting grid (text rows + per-cell `Style`).
- `Compositor::previous(&self) -> &Grid` — `pub(crate)` accessor
  the new snapshot path needs; production code never reads
  `previous` directly.
- `EngineHandle::for_test() -> (Self, Receiver<UiCommand>,
  Sender<EngineEvent>)` — the documented L3-comp prerequisite,
  shipped now even though the first L3-comp story hasn't landed
  yet (the prereq is one-line additive; postponing it gains
  nothing).

`tui::ui` module visibility: bumped from `pub(crate)` to `pub` so
integration tests can reach `Ui`, `LayoutTree`, `Buffer`, etc.
Everything inside `tui::ui` was already publicly re-exported via
`tui::theme` etc. — the bump just makes the path callers actually
type compile.

The P9-tail row in `TESTING.md` retires; L3-prim is now in P10's
hands. Interactive ("explore") and matrix-sweep runners are
deferred — neither has a current consumer, both add a proc-macro +
`inventory` dependency surface that isn't paying for itself yet.

### P10.3 — audit-driven structural cleanup ⏸

End-of-refactor audit (2026-05-06, second pass) surfaced ten items
worth landing before the parity walk. Ordered smallest → largest;
each lands in its own commit so the diff stays reviewable.

- **3.1 — Bash subpattern parser off `ToolDefaults` ✅.**
  `if bucket == "bash"` retired from
  `crates/core/src/permissions/mod.rs::check_subcommand`. New
  `SubpatternParserFn` typed alias + `subpattern_parsers:
  HashMap<String, Arc<...>>` field on `ToolDefaults` /
  `Permissions`. `tools/bash.lua` declares
  `subpattern_parser = "shell"`; `core/lua/api/tools.rs` reads the
  field and routes through `permissions::builtin_subpattern_parser`
  which only knows the Rust-built-in `"shell"` kind. Renamed
  `check_bash_against` → `shell_parser_decide`; bucket dispatch is
  now uniform over `(rs, value, mode) -> Decision`. Closes the
  last name-match leak in shared Rust.
- **3.2 — `runtime_approvals` into `Core.permissions` ✅.**
  Reverses P10.2 B1. New `approvals: Arc<RwLock<RuntimeApprovals>>`
  field on `Permissions` (interior-mutable so handlers holding
  `Arc<Permissions>` grant approvals through it; cloned permissions
  share the lock). `TuiApp.runtime_approvals` field, `TuiApp::new`
  parameter, and the parallel `Arc<RwLock<...>>` constructed in
  `main.rs` all retired; `McpDispatcher.runtime_approvals` field
  retired. Workspace approvals load through
  `Permissions::approvals.write().load_workspace(...)` in main.rs
  before the `Arc` is shared. All 13 read/write call sites in
  `app/agent.rs` + `app/engine_events.rs` route through
  `self.core.permissions.approvals`.
- **3.3 — Migrate `?` to Lua keymap (PassThrough) ✅.**
  Original audit framing — "hardcoded `run_command(self, "/help")`
  is a Lua-name-match leak" — was corrected mid-flight: `Cell<()>`
  events (`help_requested`, `esc_esc_pressed`) would still leak
  Lua-side concepts to Rust. The right shape is Lua-side keymaps
  reading buffer conditions directly. New `KeymapResult`
  (`Consumed | PassThrough | NoBinding`) on
  `core::lua::runtime::run_keymap`; handlers can `return false` to
  fall through to downstream dispatch. Migrated `?`:
  `commands/help.lua` registers `smelt.keymap.set("", "?", fn)`
  that opens `/help` when the prompt is empty (or focus is on
  content) and returns `false` otherwise — the literal `?` lands
  in the buffer when typing a real question. `KeyAction::OpenHelp`,
  the `bind(?)` entry in `keymap.rs`, and the OpenHelp arm in
  `events.rs`/`input/mod.rs` retired. Esc-Esc deferred — its
  compaction-cancel + vim-mode-restore + content/prompt focus
  nuances don't justify migration without a real plugin consumer
  (the chord-pending dispatcher state machine + `<Esc><Esc>`
  sequence support land when one shows up).
- **3.4 — Collapse per-tick `pump_lua()` ✅.**
  New `pump_lua(&mut self)` helper on `TuiApp` (in
  `app/lua_bridge.rs`) loops `drain_cells_pending` +
  `flush_lua_callbacks` until both queues are quiet — a cell
  callback can queue a Lua invocation, an invocation can set a
  cell, so the fixpoint catches the cross-feed in one pass instead
  of relying on hand-paired sites. Six paired call sites collapsed:
  `app.rs::run` tick (block_done fan-out), `app/agent.rs` turn_start
  + turn_end, `app/events.rs` input_submit, and
  `app/engine_events.rs` tool_start + tool_end. Standalone
  `flush_lua_callbacks` calls (post-`dispatch_event`,
  `drive_lua_tasks`) and the lone `drain_cells_pending` at shutdown
  stay as-is — they don't need both passes.
- **3.5 — Collapse outcome-enum salad ✅ (partial).**
  Audit framing — five enums "overlap heavily" — half held up
  under inspection: each describes a different control-flow
  domain (event dispatch, slash-command run, input submit,
  engine-event drain, main-loop step), so a one-enum collapse
  would lose meaning. The two genuine wins landed:
  - **`ExecHandle` extracted.** New `pub(crate) struct
    ExecHandle { rx, kill }` in `commands.rs`. Six sites
    storing `(Receiver<ExecEvent>, Arc<Notify>)` separately
    (`TuiApp.exec_rx` + `TuiApp.exec_kill`, three enum `Exec`
    variants, `start_shell_escape` return) collapse to a
    single struct. `TuiApp::exec: Option<ExecHandle>` replaces
    the two parallel fields.
  - **`LoopAction` retired.** The 2-variant `Continue / Done`
    enum was just a typed bool; `dispatch_control` now returns
    `bool` (true = keep draining, false = break). Five call
    sites in `app.rs::run` + `app/agent.rs` collapsed.

  `EventOutcome` (7 variants), `CommandAction` (Continue +
  Exec), `InputOutcome` (Continue + StartAgent + Exec), and
  `SessionControl` (Continue + Done + NeedsConfirm) stay —
  each carries a payload its caller actually branches on. The
  `Continue` variant repetition is a naming coincidence, not a
  collapse opportunity.
- **3.6 — Collapse `app_focus` and `transcript_window` — declined.**
  Audit framed both as parallels with `Ui` state, but closer
  inspection showed they're separate layers, not duplicates:
  - `app_focus` is logical pane focus (Prompt vs Content); it
    survives overlay opens so the dismiss path knows which pane
    to return to. `ui.focus()` is per-leaf WinId — moves to
    overlay leaves on dialog open. Folding loses the
    return-target memory and forces overlay-leaf-aware logic at
    every read site.
  - `transcript_window` carries persistent transcript state
    (cursor / scroll / vim_enabled) and is the SoT each frame.
    `ui.wins[TRANSCRIPT_WIN]` is downstream — overwritten in
    `sync_transcript_layer` from the shadow. Folding inverts
    SoT and widens `Window` semantics, with no functional gain.
  Marked done; revisit if a future change makes the layering
  itself problematic.
- **3.7 — Migrate UiHost-tier Lua bindings to `with_ui_host` — declined.**
  Audit framing assumed UiHost-tier bindings could route through
  the trait-object slot, but `UiHost` (`ui()` / `set_focus` /
  `buf_*` / `win_*` / `overlay_open` / `viewport_for` /
  `rows_for` / `breaks_for`) doesn't cover what most bindings
  need: `notify` / `notify_error`, `app.input.win.text` (prompt
  body), `app.lua` (callback queueing), `buf_create_with_id`,
  cmdline / agent / prompt-shadow state. Migrating fully would
  require expanding the trait surface in step with every
  TuiApp-specific concern (notifications, prompt buffer,
  Lua-runtime queue) — every future frontend would then have to
  impl all of it. Migrating partially leaves the
  trait-vs-concrete split scattered inside single namespaces
  (e.g. `smelt.buf.*`), harder to reason about than uniform
  `with_app`. The `UI_HOST` TLS slot stays as a future-enabler:
  when L3-comp lands and the trait grows, bindings can flip
  per-namespace without the slot needing to land then.
- **3.8 — Retire `Host` trait; expose `&mut Core` directly ✅.**
  `Host` (11 pure-getter methods) was a manual DI table with zero
  behavior — `Core::Host`, `HeadlessApp::Host`, and `TuiApp::Host`
  impls were all field delegation (`fn cells(&mut self) { &mut
  self.core.cells }`). The trait, all three impls, and the
  `pub use Host` re-export retired. The TLS slot stays —
  `*mut Core` instead of `*mut dyn Host` — under renamed
  helpers `with_core` / `try_with_core`. Inherent accessor
  methods on `Core` (same names as the old trait) keep all 54+
  Lua-binding call sites unchanged: `try_with_core(|core|
  core.cells())` reads exactly like the old form, just without
  the trait indirection. Net: -1 trait, -3 trait impls, -190
  LOC; same call surface, simpler dispatch.
- **3.9 — Decompose `TuiApp` into typed subsystems — declined.**
  TuiApp is 1282 LOC with ~50 fields, but the actual behavior is
  already well-distributed across `app/` submodules; the struct
  itself isn't obscuring anything, it's just shaped flat. Grouping
  into `Transcript` / `Prompt` / `Notifications` / `Dialogs`
  subsystems would touch ~600 call sites, force a borrow-check
  redesign at every cross-subsystem method (e.g.
  `sync_transcript_layer` simultaneously reaches transcript /
  ui / core / projection state), and either relocate `vim_mode`
  to one owner or leave it at TuiApp level. The clean shape
  isn't obvious without working through it. Without a concrete
  consumer needing the boundary (second compositor, unit-testable
  subsystem in isolation), this is organizational tidiness, not
  architectural simplification. Same call as 3.6 / 3.7.
- **3.10 — Transcript fold via `SpanMeta` extmarks — declined.**
  Audit's reversal of P10.2 E1 was itself a misread. `Buffer`
  carries `SpanMeta` **per-span** (range-based extmarks);
  `TranscriptSnapshot` carries `SpanMeta` **per-display-cell**
  (precomputed `Vec<Vec<SnapshotCell>>` for O(1) copy lookup
  at the cell granularity). The two shapes have different cost
  models. The snapshot also carries block↔row mapping
  (`block_of_row` / `row_of_block`), per-row soft-wrap flags,
  per-row source text for full-row selections, and a generation
  counter — none of which exist on Buffer.

  Replacing `TranscriptSnapshot` with Buffer extmarks alone
  would force one of: (a) walking extmarks per-cell at copy
  time on every selection (slow on large transcripts); (b)
  adding a per-cell cache to Buffer (which P10.2 E1 already
  identified as Buffer bloat); (c) keeping a bespoke per-buffer
  cache outside Buffer — which is what `TranscriptSnapshot`
  already is. The block↔row mapping and width-projection logic
  don't disappear; they relocate. P9.b and P10.2 E1 already
  considered and declined this for the same reason. Closing
  for the third time.

## Decisions made

- **Path A — drop persisted boolean settings entirely.** `init.lua`
  is the persistence story; runtime toggles (`/vim`, `smelt.settings.vim
  = true`) are transient by design. Config in init.lua is the user-facing
  contract.
- **Drop `accent_color` from the saved cache.** Themes are config —
  they live in init.lua. The `/theme` / `/color` pickers preview
  live; users wanting persistence edit their config. Same model
  Neovim uses for `:colorscheme`.
- **`ResolvedSettings` lives in `core::config`, not `core::state`.**
  Resolves directly from `SettingsConfig` with built-in defaults; no
  persistence layer between them.
- **B1 — `permissions: Arc<Permissions>` to Core (P10.3.2).**
  Original P10.2 B1 declined the move. P10.3.2 reversed it after
  finding the field already lives on `Core` (`runtime.rs:101`); the
  parallel `runtime_approvals: Arc<RwLock<RuntimeApprovals>>` on
  `TuiApp` was the actual duplicate. Folded into
  `Permissions.approvals` (interior-mutable). `TuiApp` no longer
  carries permission state.
- **E1 — Transcript stack stays multi-layered.** Folding
  `BlockHistory` + `TranscriptProjection` + `TranscriptSnapshot` +
  `BlockBufferCache` directly onto `Buffer` would either drop the
  per-cell `SpanMeta` carried by snapshots (breaking `copy_as`-aware
  yank) or push it onto every `Buffer` in the system. Neither is
  a simplification. The tractable share already landed via P9.c
  per-Block parsers and P9.r `BlockLayout`.
- **Stories example viewer ships as a non-test target.**
  `crates/tui/examples/stories.rs` reads blessed `.snap` files
  rather than re-running the harness, keeping its dependency
  surface minimal (no `mlua`, no engine wiring) and decoupling the
  viewer from in-flight story changes.
