**Status:** in-progress **Started:** 2026-05-06 **Landed:** —

P10 is the final hygiene pass after P9 lands the architectural truth.
Small, mostly mechanical. Closes the refactor.

## Scope

### 1. Saved-state cleanup + injectable constructor (landed)

Path A landed alongside Thread 2 in one edit.

**Thread 1: drop the doc lie.** `crates/core/src/state.rs` shrunk
from ~340 LOC to ~190 LOC. `PersistedSettings` (the 10-bool toggle
overlay) and the legacy field migration retired entirely; settings
no longer round-trip through JSON. `state::save_settings`,
`update_settings`'s persistence call, and the legacy
`vim_enabled` / top-level `show_thinking` migration paths all
deleted. `State` renamed to `SessionCache` with just the
genuinely cache-shaped fields: `mode`, `selected_model`,
`reasoning_effort`. `accent_color` dropped — themes are config,
they live in `init.lua` (the `/theme` and `/color` runtime pickers
are previewers; persistence comes from editing your config).

`ResolvedSettings` moved from `state.rs` to `core/config.rs`
alongside `SettingsConfig`, where it conceptually belongs.
`SettingsConfig::resolve(&self) -> ResolvedSettings` collapses the
two-phase merge into one direct call (no more
`PersistedSettings::resolve(&SettingsConfig)`).

**Thread 2: `TuiApp::new` is state-injectable.** Constructor now
takes `cache: SessionCache` as its final parameter; the internal
`state::State::load()` call is gone. `main.rs` calls
`SessionCache::load()` once via `startup::resolve` and threads it
through `ResolvedStartup` to `TuiApp::new`. Constructor is pure
modulo the `Ui::new() + terminal_size` setup — no filesystem
touch, no global state read.

Net: `state.rs` shrank ≥ 50%; the doc claim "all config in
`init.lua`" is true at the file level; `TuiApp::new` is
disk-clean and ready for L3 storybook fixture construction.

### 2. P10.2 — audit-driven cleanup batch

End-of-refactor audit (2026-05-06) found a handful of dead surfaces and
modularity wins worth landing before the parity walk. Investigated
each by call-tracing static usage; the items below are the ones whose
removal/regrouping makes the tree strictly simpler without losing
functionality.

- **A1 — Dead PredictInput / InputPrediction path.** `predict.lua`
  drives input prediction through `smelt.engine.ask({task =
  "prediction"})` + `smelt.ui.ghost_text.set`. The parallel
  `UiCommand::PredictInput` / `EngineEvent::InputPrediction` /
  `spawn_predict_request` / `predict_generation: u64` /
  `handle_input_prediction` chain is never reached (zero senders for
  `PredictInput` workspace-wide). Delete the variants, the engine
  spawn, the TuiApp field, and both engine-event arms.
- **A2 — `engine::tools::Tool` trait + ToolRegistry body.** Verified
  zero `impl Tool for` in the workspace, zero callers of
  `register_mcp` / `build_tools`. Live tool dispatch is `McpDispatcher`
  (impls `ToolDispatcher` directly) plus the Lua-tool channel via
  `UiCommand::ToolDispatch`. Replace `ToolRegistry` (60 LOC) with a
  small `EmptyDispatcher` used only by `main.rs:369` as the no-MCP
  fallback. Delete `Tool`, `ToolEntry`, `ToolEntry::is_mcp`,
  `register_mcp`, `build_tools`, `ToolRegistry::get`.
- **A3 — Unused `#[allow(dead_code)]` methods.** `BlockBufferCache::
  invalidate`, `BlockBufferCache::total_rows`, `BlockHistory::status`,
  `BlockHistory::tool_block_id`. Verified zero callers each. Delete
  the methods, drop the allow attributes.
- **B1 — `permissions: Arc<Permissions>` to Core.** Field lives on
  TuiApp today. `Permissions` itself is headless-safe (`core::
  permissions`). Promoting to `Core::permissions` lets `HeadlessApp`
  enforce permissions and moves the Lua bindings from `with_app`
  (UiHost-tier) to `with_host` (Host-tier).
- **B2 — Group cmdline state.** Four TuiApp fields used only by
  `app/cmdline.rs` (`cmdline_history`, `cmdline_history_browse`,
  `cmdline_history_stash`, `cmdline_completer`) collapse to one
  `CmdlineState` struct field.
- **C1 — Box `UiCommand::StartTurn` payload.** Drop the
  `large_enum_variant` allow. Boxing the largest variant shrinks the
  enum size for every other variant the channel ferries (`Steer`,
  `Cancel`, `PermissionDecision`, etc.).
- **D1+D2 — Stale phase-label and "legacy" comment sweep.**
  - `core/src/runtime.rs:20` — TODO referencing P8.a (P8 is done).
  - `core/src/grep.rs:8` — "until it migrates to Lua in P5.b" (P5.b done).
  - `core/src/lua/api/shell.rs:5` — "(the legacy engine `BashTool`
    owned these)" (bash tool migrated).
  - `engine/src/lib.rs:223` — "matching the streaming UX of the
    legacy engine-side `BashTool`".
  - `tui/src/app/cmdline.rs:123, 208, 248` — three "same as the
    legacy widget" lines.
  - `core/src/buffer.rs:268` and `core/src/theme.rs:114` — reword
    the `intern_anonymous_style` comment to describe its current
    role rather than the P9.e migration path. (Function still has
    six active call sites; not legacy itself.)
  - **Skip** `core/src/session.rs:312` — the meta.json sidecar
    backfill is real backwards-compat for users with pre-meta sessions
    on disk. Comment is accurate.

- **E1 — Considered, declined.** Initial audit flagged the transcript
  stack (`BlockHistory` + `StreamParser` + `TranscriptSnapshot` +
  `BlockBufferCache` + `TranscriptProjection`, ~4640 LOC) as a candidate
  for folding directly onto `Buffer` + `BufferParser`. Closer inspection
  showed the layers each carry load: `BlockHistory` is the semantic
  SoT, `StreamParser` produces the Block intermediate, per-Block parsers
  paint into per-block sub-Buffers (content-keyed cache), `TranscriptProjection`
  copies into the display Buffer once per `(generation, width)`,
  `TranscriptSnapshot` is a parallel projection that carries per-cell
  `SpanMeta` for selectable / `copy_as`-aware copy. The "duplication"
  with the display Buffer exists because `Buffer` doesn't carry per-cell
  SpanMeta and adding it would bloat every Buffer in the system.
  Folding either drops the SpanMeta-aware copy feature or relocates
  the same logic onto `Buffer` — neither is a simplification.
  P9.c stage 1 (per-Block parsers under `transcript_parsers/`) +
  P9.r (`BlockLayout` return shape) already landed the tractable
  share of the keystone; the remaining "fold" is not a code-quality
  win.

### 4a. L3-prim storybook lands

`crates/tui/tests/storybook/` ships with the harness (`StoryCtx`,
`Ui::snapshot`, `SnapshotFrame`, `story!` macro) and 8 initial
stories across `layout / overlays / theme / vim`. Two snapshot
files per story (`<id>.snap` text + `<id>.styles.snap` per-cell
style sidecar) keep colour-only and wrap-only diffs surgical;
`insta` is the existing snapshot library.

Three additive seams landed alongside:
- `Ui::snapshot(&mut self) -> SnapshotFrame` — renders into the
  compositor through an `io::sink()` writer, returns a structured
  copy of the resulting grid (text rows + per-cell `Style`).
- `Compositor::previous(&self) -> &Grid` — `pub(crate)` accessor
  the new snapshot path needs; production code never reads
  `previous` directly.
- `EngineHandle::for_test() -> (Self, Receiver<UiCommand>,
  Sender<EngineEvent>)` — the documented L3-comp prerequisite,
  shipped now even though the first L3-comp story hasn't landed
  yet (the prereq is one-line additive; postponing it gains
  nothing).

`tui::ui` module visibility: bumped from `pub(crate)` to `pub` so
integration tests can reach `Ui`, `LayoutTree`, `Buffer`, etc.
Everything inside `tui::ui` was already publicly re-exported via
`tui::theme` etc. — the bump just makes the path callers actually
type compile.

The P9-tail row in `TESTING.md` retires; L3-prim is now in P10's
hands. Interactive ("explore") and matrix-sweep runners are
deferred — neither has a current consumer, both add a proc-macro +
`inventory` dependency surface that isn't paying for itself yet.

## Decisions made

- **Path A — drop persisted boolean settings entirely.** `init.lua`
  is the persistence story; runtime toggles (`/vim`, `smelt.settings.vim
  = true`) are transient by design. Config in init.lua is the user-facing
  contract.
- **Drop `accent_color` from the saved cache.** Themes are config —
  they live in init.lua. The `/theme` / `/color` pickers preview
  live; users wanting persistence edit their config. Same model
  Neovim uses for `:colorscheme`.
- **`ResolvedSettings` lives in `core::config`, not `core::state`.**
  Resolves directly from `SettingsConfig` with built-in defaults; no
  persistence layer between them.
