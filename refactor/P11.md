# P11 — UI generalization (renderer-as-a-library)

**Status:** A + B + C landed **Drafted:** 2026-05-07 **Last updated:** 2026-05-07

Final crate names landed slightly differently from the original draft:
- `smelt-ui-data` → `smelt-buffer` (data layer; renamed once it became
  clear the crate carries `Buffer` as much as it carries `Style`/`Theme`).
- `smelt-render` → `smelt-term` (renderer; "terminal rendering library"
  reads truer than the abstract "render").
- `smelt-editor` → `smelt-edit` (editor layer over `smelt-term`).
- `crates/tui` re-export shim is `pub use ::smelt_edit as smelt_term;`
  — keeps every `crate::smelt_term::*` path in tui working unchanged.

P11 generalizes `crates/ui` so it's usable outside smelt — first as a
proof point via `tcloc` (a treemap TUI), eventually as a credible
standalone TUI library. The work splits into three phases, each green
at the boundary; nothing depends on a downstream phase landing.

The driving signal: a one-day port of `tcloc` (1500 lines, ratatui-based)
to `smelt-ui` surfaced six concrete API gaps, plus one architectural
question (renderer/editor coupling) worth answering deliberately.

Background: see the tcloc port in `<other-repo>/.claude/worktrees/smelt-ui-port/`.
Smelt-ui changes from that port already exist as unstaged edits in this
worktree (`crates/ui/src/{layout,grid,lib}.rs`,
`crates/ui-data/src/style.rs`).

## Decisions made

- **Min(n) = ratatui semantics, not "exactly n".** Floor that competes
  with Fill for leftover. The current `Length`-equivalent behaviour
  caused a real bug in the tcloc port (treemap collapsed) and
  contradicts the docstring. Storybook test rebaselines.
- **`Style` constructors retire in favour of a single `Style::new()`
  + chainable setters.** `Style::fg(c)` / `Style::bg(c)` / `Style::bold()`
  become `Style::new().fg(c).bg(c).bold()`. Spread (`..Style::default()`)
  keeps working unchanged.
- **`slice.put_char(x, y, ch, fg)` as a partial-update primitive
  alongside `slice.set` (full overwrite).** Preserves existing bg
  when only fg changes — fixes the latent "label paints over coloured
  tile and blanks the bg" bug.
- **Lib name aligns with package name (`smelt_ui`, not `ui`).** Drops
  the `pub use ::ui;` re-export trick; downstream consumers stop
  needing the Cargo.toml dep alias.
- **Generic `HitTarget<P>` with user payload.** Editor specialises to
  `HitTarget<WinId>`; tcloc-class consumers attach their own tile
  payload. Eliminates the per-app hand-rolled hit table.
- **Chrome titles take styled text (`Line` not `String`).** With
  `impl From<&str> for Line` so existing callers stay one-line.
- **Renderer types are public stable surface** (`Compositor`,
  `flush_diff`, `Cell`, `GridSlice`, `Grid::cell_mut`). Most are
  already exposed after the tcloc port; this phase commits to it.
- **`DrawContext::theme: Arc<Theme>`, not cloned per leaf.** Theme is
  read-only during paint; sharing via Arc kills the per-frame clone.
- **Crate split: `smelt-render` + `smelt-editor` (sharing `smelt-ui-data`).**
  The renderer becomes a standalone TUI library; the editor is a layer
  on top. `pub use ::smelt_editor as ui;` shim in `crates/tui` keeps
  smelt's existing `crate::ui::Foo` paths working unchanged.
- **Unified `PaintId` leaf type, not generic `LayoutTree<L>`.** Editor
  side defines a paint dispatcher that routes WinId-domain paint ids
  to `Window::render` and others to user code. Avoids generic
  specialisation friction in downstream consumers.
- **Skipped:** Cell representation packing, direct-byte emission,
  per-leaf chrome, dropping `Color::Reset`. None of these enable real
  use cases; their cost-benefit is upside-down.

## Phase A — quick wins (one PR, ~200 LOC)

Self-contained; nothing depends on downstream phases. Pure correctness +
ergonomics.

### A.1 — fix `Constraint::Min(n)` semantics

**What:** `Min(n)` becomes "at least n cells, share remainder with
Fill/Fit." Currently it's a hard `Length(n)` equivalent.

**Algorithm:** in pass 3 of `resolve_constraints`, treat `Min(n)`
identically to `Fill` for the equal-share split, then clamp each
Min child to a minimum of `n`. If the floors collectively exceed
remaining, Min children take their floors first; Fills take what's
left (possibly 0).

**Files:**
- `crates/ui/src/layout.rs:645` (`resolve_constraints`)
- `crates/ui/src/layout.rs:800` (`min_reserves_floor_then_competes_with_fill`
  test — rebaseline assertion from "Min=3, Fill=21" to the new spec)
- `crates/tui/tests/storybook/stories/layout.rs:117,237` (visual stories
  that use Min — verify they still render meaningfully)

**Done when:** Min(0) on a sole flex child consumes all remaining;
Min(n) + Fill split equally with Min having floor n; the layout test
suite is green with rebaselined assertions.

### A.2 — fluent `Style` builders

**What:** Drop the constructor methods (`Style::fg`, `Style::bg`,
`Style::bold`, `Style::dim`). Add a single `Style::new()` plus chainable
setters that take and return `Self`. The fluent builders I added in the
tcloc pass (`with_fg`/`with_bg`/`with_bold`/`with_dim`) consolidate into
the canonical `fg`/`bg`/`bold`/`dim` chain methods.

**Migration:** `Style::fg(c)` → `Style::new().fg(c)`. Sed-able. Spread
(`..Style::default()`) unchanged.

**Files:**
- `crates/ui-data/src/style.rs`: drop the four constructors, replace
  with chain methods; keep `Style::default()`.
- `crates/tui/src/theme.rs:244-276`: ~25 sites flip to `Style::new().fg/bg`.
- `crates/tui/src/picker.rs`, `crates/tui/src/app.rs`,
  `crates/tui/src/app/render_loop.rs`, `crates/tui/src/content/status.rs`,
  `crates/tui/src/content/transcript_parsers/{exec,markdown}.rs`,
  `crates/tui/src/content/prompt_buf.rs`,
  `crates/tui/src/lua/api/buf.rs`: ~50 more sites total, mechanical.

**Done when:** every `Style::fg|bg|bold|dim(...)` constructor call has
been migrated to `Style::new().fg|bg|bold|dim(...)`; `cargo test
--workspace` green; `grep -r "Style::fg\b\|Style::bg\b\|Style::bold\b\|Style::dim\b"`
in smelt returns zero.

### A.3 — bg-preserving partial cell update

**What:** Add `slice.put_char(x, y, ch, fg)` that reads the existing
cell, sets only `symbol` and `style.fg`, leaves `style.bg` untouched.
Same for a `slice.put_str` partial variant. Keep `slice.set(x, y, ch,
style)` as the full-overwrite primitive.

**Why:** any extmark with `fg` set but `bg = None`, painted over a
coloured row (cursor-line highlight, visual selection, inline diff
markers), currently blanks the bg and falls back to terminal default.
The tcloc port hit this exact issue (labels over half-block tiles
losing the tile colour).

**Files:**
- `crates/ui/src/grid.rs`: add the two partial primitives (Cell +
  GridSlice level).
- `crates/ui/src/window.rs`: in `Window::render` (~line 1033), audit
  every `set` / `put_str` against the extmark composition path; switch
  to partial variants where the caller doesn't intend to overwrite bg.
  Roughly the highlight-extmark application loop and the cursor-block
  painter.
- New test in `crates/ui/src/grid.rs` exercising "put_char over a
  pre-painted bg cell preserves the bg."

**Done when:** new tests pass; a smelt-side test paints a coloured row,
overlays a fg-only extmark, asserts the bg is preserved.

### A.4 — lib name = `smelt_ui`

**What:** rename `[lib] name = "ui"` → `[lib] name = "smelt_ui"` in
`crates/ui/Cargo.toml`. Same for `crates/ui-data` (`name = "smelt_ui_data"`).

**Migration:** every `crate::ui::Foo` in the tui crate becomes
`crate::smelt_ui::Foo`. Re-export in `crates/tui/src/lib.rs` flips
from `pub use ::ui;` to `pub use ::smelt_ui;`. Lua bridge (`lua/api/*`)
is mechanical.

**Files:** ~40 files in `crates/tui/src/`. Sed-able.
- `crates/ui/Cargo.toml`, `crates/ui-data/Cargo.toml`
- `crates/tui/src/lib.rs:24` (re-export)
- All ~40 `crates/tui/src/**/*.rs` files using `crate::ui::`

**Done when:** `cargo build --workspace` green; `grep -r "::ui::\b\|crate::ui::\b"`
in smelt's tui crate returns zero matches outside the re-export line.

## Phase B — generalize the API surface (one PR, ~300 LOC)

Builds on A. Makes the renderer more pluggable without splitting it.

### B.1 — generic `HitTarget<P>`

**What:** `HitTarget` becomes generic over a host-supplied payload.
Editor specialises to `HitTarget<WinId>`. tcloc-class consumers attach
their own payload (e.g. `HitTarget<TileTarget>`). The chrome /
scrollbar variants stay editor-specific behind a feature flag or
co-located with the editor's specialisation.

**Shape:**
```rust
pub enum HitTarget<P> {
    Inside(P),
    Chrome { owner: P, zone: ChromeZone },
    Scrollbar { owner: P },
}

impl Ui {
    pub fn record_hit(&mut self, rect: Rect, payload: P);
    pub fn hit_test(&self, row: u16, col: u16) -> Option<&HitTarget<P>>;
}
```

**Files:**
- `crates/ui/src/overlay.rs`: HitTarget definition.
- `crates/ui/src/lib.rs:215,459,865` (`resolve_split_mouse`, `hit_test`,
  `capture` — generic param threaded through).
- `crates/tui/src/app/mouse.rs:28-29`,
  `crates/tui/src/app/render_loop.rs:105`: turbofish `HitTarget::<WinId>`
  on the pattern matches. Two-line touches.
- tcloc-side: drops the hand-rolled `Vec<(Rect, TileTarget)>` table;
  uses `ui.record_hit` + `ui.hit_test`. ~30 LOC reduction in tcloc.

**Done when:** smelt builds with no behaviour change; tcloc's
`last_tiles` field deletes; mouse handling routes through `Ui::hit_test`.

### B.2 — styled chrome titles

**What:** `Chrome::title: Option<Line>` (was `Option<String>`). `Line`
is the styled-text type from B.3.

**Migration:** `impl From<&str> for Line` so existing string callers
keep working. New chained API: `tree.with_title(line!["foo", " ", styled(",bar", DIM)])`.

**Files:**
- `crates/ui/src/layout.rs:60` (`Chrome` struct), `:143-146`

- `crates/tui/src/lua/ui_ops.rs:78` (Lua bridge — string passthrough

- Storybook tests: ~10 sites need a `.into()` if Rust doesn't infer.

**Done when:** smelt's chrome behaviour unchanged; tcloc's two-coloured
treemap title uses `with_title(...)` instead of hand-painted borders.

### B.3 — `Line` and `Span` styled-text types

**What:** Add `Span<'a> = (Cow<'a, str>, Style)` and `Line<'a> = Vec<Span<'a>>`.
Add `slice.put_line(x, y, &Line)` primitive that handles the styled-run
write in one call.

**Why:** every TUI consumer reaches for this. Replaces
`put_str_clip(...)` chains in tcloc's footer/header/bench (~80 LOC of

**Files:**

- Optional: `line![]` macro for terse construction.
- Wire into B.2's chrome titles.

**Done when:** tcloc's footer row goes from a 12-line `put_str_clip`
chain to a 1-line `slice.put_line(0, 0, &line![ ... ])` call.

### B.4 — promote renderer types to public surface

**What:** flip `pub(crate)` → `pub` for `Compositor`, `flush_diff`,
`Cell`, plus their dependencies.

**Files:**
- `crates/ui/src/lib.rs:2-4` (visibility on the module re-imports).

**Done when:** an external crate can use `Compositor::new`,

### B.5 — `DrawContext::theme: Arc<Theme>`

**What:** swap `theme: Theme` (cloned per leaf per frame) for
`theme: Arc<Theme>`. `ctx.theme.get(name)` keeps working unchanged

**Files:**
- `crates/ui/src/window.rs:29` (`DrawContext` field).
- `crates/ui/src/lib.rs:1757` (`paint_layout_node` constructs ctx —
  switch the clone to `Arc::clone`).
- `crates/ui/src/lib.rs:80` (`Ui` holds `theme: Arc<Theme>`).

**Done when:** per-frame allocation count for a fixed-content frame
decreases by `n_leaves` (verifiable via tcloc's `alloc_track`).

## Phase C — split smelt-term from smelt-edit (LANDED)

The headline architectural move. Landed in commits:
- `55effb4d` — C.0 unify `LayoutTree::Leaf` via `PaintId` (u32 → u64).
- `4b28b9f0` — C.1 + C.2 carve `smelt-edit` out of `smelt-term`, flip tui.

Final crate name mapping (vs the original draft):
- `smelt-render` → **`smelt-term`** (under `crates/term/`).
- `smelt-editor` → **`smelt-edit`** (under `crates/edit/`).
- `smelt-ui-data` → **`smelt-buffer`** (under `crates/buffer/`).

### C.1 — what moves where (final)

**`smelt-term` (renderer, ~90-line `lib.rs` index + 7 modules):**
- `geometry.rs` — `Rect`.
- `grid.rs` — `Grid`, `Cell`, `GridSlice`, `Style`, partial-update
  primitives (`put_char`, `put_str_fg`, `put_line`).
- `compositor.rs` — `Compositor`, double-buffered diff/flush.
- `flush.rs` — SGR diff emit (`flush_diff`).
- `layout.rs` — `LayoutTree`, `Constraint`, `Chrome`, `Border`,
  `BorderSides`, `Gutters`, `Corner`, `Anchor`, `paint_chrome`,
  `resolve_layout`, `resolve_constraints` (now `pub`), `PaintId(u64)`.
- `line.rs` — `Line`, `Span` (B.3 product).
- `hit.rs` — `HitRegistry<P>` typed hit-region table.
- `snapshot.rs` — `SnapshotFrame` for testing.
- `lib.rs` re-exports the public surface and provides a single host
  entry point: `paint_layout_tree(grid, theme, node, area, term_size,
  paint)` that walks a `LayoutTree`, paints chrome, and dispatches each
  leaf to a host-supplied `PaintDispatch` callback. The renderer
  ascribes no semantics to `PaintId`.

**`smelt-edit` (editor layer):**
- `window.rs` — `Window`, `DrawContext`, `WindowViewport`,
  `ScrollbarState`, `CursorShape`, `SplitConfig`. Pulls `GridSlice`,
  `Style`, `Gutters`, `Rect` from `smelt_term`.

- `event.rs` — `Event`, `Status`.
- `overlay.rs` — `Overlay`, `OverlayId`, `Anchor` resolution; the
  internal `paint_overlay` clears the rect then defers to
  `smelt_term::paint_layout_tree`.
- `lib.rs` (was 3676 lines, now ~2070 — 8 sibling modules moved out)
  defines `WinId(u64)` with `From<WinId> for PaintId`, `LuaInvoke`,
  and the `Ui` struct + impl. `Ui::render` builds an editor-aware
  `PaintDispatch` closure that maps `PaintId → WinId → Window::render`
  and forwards unknown ids to a host paint callback. Also re-exports
  the renderer surface via `pub use smelt_term::{grid, layout, ...}`
  so existing `crate::smelt_term::*` paths in tui keep resolving.

**`smelt-buffer` (renamed from `smelt-ui-data`, unchanged in scope):**
- Both crates depend on it.
- `Theme`, `Style` colours, `Color`, `Buffer`, extmarks, undo,
  attachments, clipboard.
- (`Buffer`/extmarks/undo/attachments are editor-flavoured but ship in
  `smelt-buffer` because `Theme` is shared. Acceptable — `smelt-buffer`
  stays the shared-data layer.)

### C.2 — the `LayoutTree::Leaf(WinId)` problem (resolved)

Resolved by C.0: `LayoutTree::Leaf(WinId)` retired. `LayoutTree::Leaf`
now carries only `PaintId`. The editor's `Ui::render` constructs a
`PaintDispatch` closure that:
1. Looks up `PaintId` against the editor's `WinId → Window` registry
   (via `WinId(id.0)` since `PaintId` and `WinId` share a 1:1 numeric
   relationship — `From<WinId> for PaintId` is provided).
2. If found, dispatches to `Window::render` with the window's buffer +
   draw context.
3. Otherwise, forwards to the host's paint callback.

`Anchor::Win.target` likewise widened to `PaintId`. Crossings at the
tui boundary (e.g. `PROMPT_WIN: WinId` flowing into `Anchor::Win`)
take an explicit `.into()`.

### C.3 — `PaintId` widening (landed)

`PaintId(u32)` → `PaintId(u64)`. Carries a full `WinId(u64)` round-trip
without truncation.

## Out of scope

These came up during the audit and are explicitly *not* worth doing
now:

- **Cell representation packing** (Cell from ~56 bytes → ~16 bytes
  via packed style). No correctness gain; risks subtle equality
  miscompares in test infrastructure; current memory is fine.
- **Direct-byte ANSI emission for hot leaves** (bypass diff per row).
  Speculative perf; tcloc's frame budget is fine; smelt's never been
  close to budget.
- **Per-leaf chrome** (`LayoutTree::Paint(_).with_border(...)`).
  Wrap-with-vbox is 3 lines; not worth a `Decorate` enum variant.
- **Drop `Color::Reset`.** Touches 81 sites in smelt + ~10 in Lua
  bridge. Semantic gain (one canonical "no colour") is small.
- **Generic `LayoutTree<L>`.** Considered — rejected in favour of
  unified `PaintId` (C.2). Generic specialisation friction in
  downstream consumers outweighs the type-safety gain.
- **Cassowary-class layout solving.** Min/Max/Length/Fill/Ratio cover
  ~100% of real TUI layouts. Constraint solving is a feature trap.
- **Async paint.** Terminal frames are 33ms. Anything longer should
  pre-compute outside the paint loop.
- **Retained scene-graph.** Immediate-mode is the right model for
  terminals.

## Order and shipping

Phases land independently. Each is a single PR.

1. **A** (4 items, ~200 LOC). Quick wins, no architectural commitment.
2. **B** (5 items, ~300 LOC). Generalises the API. Sets up for either
   an in-place future or the C split.
3. **C** (8 items, ~one focused day). The split. Only if there's at
   least one external consumer beyond tcloc, or you want smelt-render
   to be a credible standalone library.

If only A lands, smelt and tcloc both get strictly better. If A + B
land, the API is meaningfully more general without changing crate
boundaries. C is the "make it a public library" commitment.
